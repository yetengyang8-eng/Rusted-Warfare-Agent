## 问题和变更

Spain A 有 137 次工程师菜单、93 次空队列，但 cost=3500 的工程师从未在菜单中可负担。普通出兵持续消耗收入；一段约 239 游戏秒的部分门槛窗口内花掉 15200。原始行号、SHA、8 个需求去向及反事实限制见 [ANALYSIS.md](ANALYSIS.md)。该发现足以定位资金积累断点，不构成两局整体分化的完整根因。

新行为是为一个真实未服务能力需求、一个生产者及其真实菜单动作预留全价。只有满足既有军力与安全条件，且按已有收入模型估算缺口不超过 60 游戏秒时才开始。期限为 90 游戏秒；需求取消/已服务、基地受威胁、军力低于 6、生产者丢失、安全容量用尽或工程师已足够时释放。下一合法行动核对菜单与价格，变化或拒绝也释放。取消/超时/失败后冷却 60 游戏秒；成功不施加失败冷却。

普通出兵、工厂升级与新建的可选经济投资必须留下这笔资金。已承诺工程师购买先于 worker 行为获得合法下令机会，仍经过共享命令仲裁器。原有 Builder 恢复、经济底线补矿、已经存在的施工/矿投资/工厂目标承诺保持原优先级；它们可能延长积累，所以有期限和取消条件。战略投资及施工使用扣除预留后的余额。工程师支付时只扣独立硬储备，避免把自己的预留再次扣除。

预留开始和释放分别记录 `strategy_capability_reserve_started` / `strategy_capability_reserve_released`，包含需求、生产者、动作、原生价格、时限和原因；普通生产让位记录 `production_deferred reservedFor=CAPABILITY_PURCHASE`。该变更不引入隐藏动态敌情、额外原生反射或新的兵种行为。
